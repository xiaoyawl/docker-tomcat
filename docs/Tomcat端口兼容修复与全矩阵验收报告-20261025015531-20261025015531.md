# Tomcat HTTP端口兼容修复与全矩阵验收报告

创建及修改：20261025015531（北京时间）。维护者：Manta <manta.ops.dstw@gmail.com>。

## 问题与修复

- 旧启动脚本使用 TOMCAT_HTTP_PORT 修改 HTTP Connector；此前的新入口遗漏该变量，容器实际仍监听8080。在 host 网络中，ports 映射不能替代应用监听端口配置。
- 此前的8080首页、JSP、安全探针验收有效，但没有覆盖非默认端口，不能证明旧端口变量兼容。
- 新默认 server.xml 使用 `${dstw.tomcat.http.port:-8080}`；入口校验 TOMCAT_HTTP_PORT 后追加对应系统属性至 CATALINA_OPTS。保留已有 JAVA_OPTS、CATALINA_OPTS，启动时不改写 server.xml。
- 不设或置空变量时保持8080；固定端口范围1～65535，使用十进制处理前导零。Shell回归覆盖1、9027、09027、65534、65535，以及0、65536、99999、100000、负数、非数字和算术表达式拒绝。
- 自定义挂载 server.xml 若需要使用环境端口，必须包含上述占位符；自定义文件的硬编码端口由该文件控制。

- Alpine3.24、CentOS Stream9、Rocky Linux9共39组合；78个平台运行结果、156个默认/非默认端口场景全部通过。
- 每个平台实际运行证书扫描、正常HTTPS、Java/Tomcat版本检查；默认8080静态页面及9027 JSP请求均通过。JSP同时验证 Etc/GMT+4 时区（实际值为 `Etc/GMT+4`）、原CATALINA_OPTS标记和运行时版本。
- 补充对业务候选Tomcat9/JDK8 Alpine在amd64及arm64实际监听65535并请求JSP，确认端口上限可用。
- 默认及非默认场景均使用只读挂载的该镜像原生 server.xml，配置内容在前后保持一致。
- 安全探针使用JDK8编译的Java8字节码跨架构执行；JSP由各平台的Tomcat/JVM实际处理。amd64原生、arm64为QEMU模拟，未做ARM真机验收。
- JDK15个基础镜像继续使用20261024批次；公开index与原始OCI一致、所有基础blob哈希通过校验。
